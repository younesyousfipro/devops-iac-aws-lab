# Decisions

DevOps decisions for this repository, recorded when they are made. The starting point is the OpenClassrooms starter kit (first commit), adapted to production-like practices.

## Hosting and repository (2026-11-09)

| Decision | Rejected | Reason |
|---|---|---|
| AWS for the three exercises | local Docker option; Azure | the starter kit covers AWS for all three exercises (managed OpenSearch for Ex2); the Ex1 Docker option boots a QEMU VM that needs `/dev/kvm`, not available on macOS; Azure only appears in the Ex3 title, with no starter files and no managed OpenSearch equivalent. Consequence: real costs, covered by the AWS Free plan credits; every session ends with `terraform destroy` |
| One repository, one folder per exercise (`01-provision-configure`, `02-observability-elk`, `03-load-balancing`) | one repository per exercise | the brief asks for one repository; the exercises are small; each folder has its own Terraform state, so nothing is shared |
| Hosted on GitHub as `devops-iac-aws-lab` | GitLab (named in the brief) | GitHub is the author's main platform; the Ex1 deliverable asks for a GitHub link; the deliverables are also uploaded as a zip |
| Starter kit history kept (initial commit), `origin` changed | fresh `git init` | the diff between the starter kit and this work stays visible, and the kit stays credited |
| Repository docs in English | French | readable by anyone reviewing the repository |

## Terraform foundations (2026-11-09)

| Decision | Rejected | Reason |
|---|---|---|
| Remote state in S3, native locking (`use_lockfile = true`) | local state; DynamoDB locking | the state survives the laptop and is locked during an apply; native S3 locking (Terraform 1.10+) replaces DynamoDB, now deprecated |
| State bucket created by a separate `00-bootstrap/` folder, with local state | bucket created by hand in the console | the bucket is code too; its own state holds nothing sensitive. Consequence: the bucket is not destroyed at the end of a session (cost: a few cents at most) |
| Existing public key registered with `aws_key_pair` (dedicated `id_ed25519_aws`) | key generated by Terraform (`tls_private_key`, starter kit) | a generated private key is stored in clear in the state; with an existing key, the private key never leaves the laptop |
| Production-like hygiene: SSH open to the author's IP only, pinned recent provider versions, AMI looked up by a data source | starter kit defaults (`0.0.0.0/0`, provider `~> 4.16`, hard-coded AMI) | least privilege; reproducible versions; an AMI ID gets outdated and differs by region |
| Default VPC | custom VPC with private subnets | private subnets need a NAT gateway, which is billed per hour; high availability is out of scope for these exercises |

## AWS account (2026-11-09)

| Decision | Rejected | Reason |
|---|---|---|
| Keep the account created with "Sign up for AWS (new)": one project `devops-iac-aws-lab` (= one AWS account), owned by an AWS Builder ID with MFA | activate advanced features; new account with "Sign up for AWS (advanced)" | simplest secure setup: no root user, no IAM user, no long-lived key; Organizations, Identity Center and the admin role are managed by AWS; every service of the three exercises is supported (EC2, VPC, S3, IAM, OpenSearch Service, Elastic Load Balancing). Activating advanced features is irreversible and requires the Paid plan first. Consequence: IAM users can only be used for programmatic access; region and service list are imposed |
| Region `eu-north-1` (Stockholm) | `eu-west-3` (Paris, first proposal); `us-east-1` (starter kit) | imposed by the project (chosen from the contact address); no impact on these exercises. Consequence: all exercises run in `eu-north-1` |
| CLI authentication with `aws login` (temporary credentials of `AccountFullAccessRole`, valid 12 h, renewable for 90 days) | IAM user access keys | no long-lived secret on the laptop. Consequence: Terraform must read the `login_session` profile (Terraform 1.15+ and AWS provider 6.23+, to be checked in the official changelog); fallback: `aws configure export-credentials --format env` |
| Cost guardrails: Free plan (no charge possible, until 2027-05-09, USD 100 credits) and an AWS Budgets alert | no alert | the Free plan caps the cost; the alert shows credits being consumed. Consequence: every session still ends with `terraform destroy` |

## State bootstrap (2026-11-11)

| Decision | Rejected | Reason |
|---|---|---|
| Terraform `~> 1.17` (1.17.1 installed), AWS provider `~> 6.72` (6.72.0, 2026-11-04); exact versions locked by the committed `.terraform.lock.hcl` | starter kit `~> 4.16`; no constraint | latest stable releases, checked on releases.hashicorp.com and the provider changelog; `~>` accepts fixes and features, not a new major version. Reading the `aws login` session needs Terraform 1.15+ (S3 backend) and provider 6.23+ |
| Files split as in the official style guide: `terraform.tf`, `providers.tf`, `backend.tf`, `main.tf`, `variables.tf`, `outputs.tf` | one `main.tf`; `versions.tf` | a reviewer knows where to look; this is HashiCorp's documented convention |
| `prevent_destroy` on the state bucket | no protection | every session ends with `terraform destroy`; run by habit in `00-bootstrap/`, it would delete the bucket holding every state. Consequence: deleting the bucket at the end of the project requires removing this line first |
| State bucket settings: versioning and the four S3 Block Public Access settings declared in code; encryption left to the S3 default (SSE-S3) | explicit `aws_s3_bucket_server_side_encryption_configuration`; SSE-KMS | versioning is the only setting S3 does not enable by default, and it allows rolling back a damaged state; public access is blocked by default but can be reopened, so AWS recommends the four settings on each bucket (Security Hub S3.8) and Terraform then detects a manual change; SSE-S3 applies to every object since 2023-01-05 and cannot be turned off, so declaring it adds nothing; SSE-KMS adds cost for no gain here |

## Exercise 1 layout (2026-11-11)

| Decision | Rejected | Reason |
|---|---|---|
| Docker variant of Ex1 removed (`terraform/docker/`, `ansible/hosts_docker`); `terraform/aws/` flattened into `terraform/` | keep both variants | the Docker option is not used (QEMU needs `/dev/kvm`); dead code makes a reviewer wonder which variant is the real one; the files stay in the starter kit commit. The Docker variants of Ex2 and Ex3 are decided in their own branches |
| Kit `main.tf` removed at piece 3a, rewritten at 3b (instance, security group, key pair) | keep it while adding `terraform.tf` and `providers.tf` | its `terraform {}` and `provider "aws"` blocks would duplicate the new ones, and its `tls`/`local` resources would add two unused providers to the lock file. The original stays in the starter kit commit |
| Backend values written in the code, account ID included (`devops-iac-aws-lab-tfstate-271802700738`) | partial configuration (`-backend-config=backend.hcl`, git-ignored) | a backend block cannot read variables; AWS does not treat an account ID as a secret (it grants nothing without credentials); a reviewer sees where the state lives. Consequence: the account ID is public on GitHub; in a company, the repository would be private |
| Each block is preceded by one or two lines saying what it is and what it is for here, followed by the link to its official doc page | the registry's one-line description ("Provides a security group resource"), which names the block without explaining it; no links | someone who has never seen a security group understands its role; the code can be checked against its source in one click. Consequence: links to update if HashiCorp moves its pages |
| Security group rules as separate `aws_vpc_security_group_ingress_rule` / `egress_rule` resources; outbound allow-all declared explicitly | inline `ingress {}` / `egress {}` blocks (starter kit) | the provider docs call separate rules the current best practice; inline blocks conflict with them. Terraform removes the AWS default egress rule, and apt needs outbound access |
| SSH (22) open to the admin IP only; HTTP (80) open to anywhere | SSH from `0.0.0.0/0` (starter kit); HTTP restricted to the admin IP | least privilege for administration; port 80 is the web server's purpose, and the starter kit did not open it at all (step 7 would fail) |
| Admin IP in a variable, its value in a git-ignored `terraform.tfvars` | IP written in the code | a personal IP does not belong in a public repository (unlike the account ID, it identifies a person). Consequence: when the home IP changes, update one line; a reviewer without the file is prompted for the value at plan |
